# v0.3 设计笔记：先建评测，再做本地优先的论文查询

## 这一版要解决什么

v0.2 留下了两个问题：

1. **路由好不好只能靠肉眼看。** 只有 7 个测试问题。改了提示词以后，无法判断是变好了，还是把原本对的改错了。
2. **`library` 和 `search` 的边界划错了维度。** "Tell me about X paper" 应该交给谁，取决于 X 在不在本地库里。这件事让路由器去猜，它只能对照提示词里的标题列表来判断。

v0.3 的做法：**先建评测，让每次改动都有数字可比；再把"论文在不在本地"这个判断从模型手里拿出来，交给代码。**

```text
library_node（子图）
  START -> resolve_local（查元数据，代码匹配）
             ├─ 找到   -> local_rag（FAISS，按 paper_id 过滤）   ─┐
             └─ 没找到 -> external_retrieval（复用 search_papers）─┴-> answer（模型只负责写回答）-> END
```

## 关键设计决策

### 1. 先建评测，再改代码

`evals/eval_router.py` 只调用路由器的 `split_question()`，不跑整张图。这样既不需要 MCP Server，也不访问网络，34 道题跑 3 遍大约 4 分钟。

它报告四类指标：

- 类别集合完全一致的比例，单任务题和多任务题分开算
- 每个类别的 precision / recall
- 稳定性：同一道题跑多遍，结果是否一致
- 错题列表：附上每次拆出的子问题

**类别对不对，用代码判断。** 子问题写得好不好暂时不打分，只在错题里打印出来，供人工查看。能用确定性规则判断的指标就不交给 LLM-as-judge，这和 v0.2"能用确定性规则解决的，就不要交给模型"是同一个原则。

开发过程中有两个值得记住的教训：

- **第一版评测集一跑就是 100%。** 26 道常规题区分不出路由器的好坏。加了 8 道故意设陷阱的题以后（提到库里的论文却问的是笔记、中文提问、需要串行依赖的问题），才测出 "Tell me about the Mask R-CNN paper" 有 2/3 的概率被分到 `library`。**满分的评测集提供不了信息，这时应该加更难的题。**
- **评测脚本自己也会有 bug。** library 评测第一次跑出来，库内题目是 0/30。原因是分割器生成的标题行是 `## CellViT  `，末尾带两个空格，我的字符串匹配没考虑到。**结果明显反常时，先怀疑测量工具，再怀疑被测的代码。**

### 2. `library` 和 `search` 按意图划分，不按数据来源划分

| | `search` | `library` |
| --- | --- | --- |
| 用户想做什么 | **发现**：这个方向有哪些论文、有哪些和 X 相似的论文 | **深挖**：某篇具名论文的方法、数据集、指标 |

改动之前，"某篇具体论文"要再按"在不在本地库里"拆成两类。路由器只能对照标题列表来猜，所以 Mask R-CNN 会被分错。改动之后，路由器只判断意图，"在不在库里"交给 library 内部的代码判断。路由提示词里的标题列表也删掉了。

注意：这次改动之后，路由评测在 3 轮里都是 35/35。但 Mask R-CNN 那道题的**标注**也从 `search` 改成了 `library`，因为 `library` 的定义变了。所以这个满分不能和之前的 98% 直接比较。

### 3. 提示词里只放规则，不放论文列表

把本地库的所有标题写进提示词，在 6 篇论文时还能工作，但这种做法无法扩展：

- 标题列表会随着库变大而变长，每次请求都要带上，占用上下文
- 对某一个问题来说，绝大多数标题都和它无关
- 论文目录本来应该存在数据里，而不是写在提示词里

所以 v0.3 的路由器和 library 的回答模型，提示词里都没有论文名。

### 4. 元数据和 chunk 分开存放

| 数据 | 存在哪里 | 回答什么问题 |
| --- | --- | --- |
| 论文元数据（`paper_id`、标题、别名） | `data/papers.json` | **我有没有这篇论文？** |
| 论文内容的 chunk | FAISS，每个 chunk 带 `paper_id` | **这篇论文的哪一段能回答这个问题？** |

`split_papers()` 在切分时，会根据 `papers.json` 给每个 chunk 打上 `paper_id`。`papers.md` 里的论文如果在 `papers.json` 里找不到对应记录，就直接报错，因为这样的论文永远不可能被找到。旧的 FAISS 索引里没有 `paper_id`，启动时会自动重建。

`local_rag` 检索时使用 `filter={"paper_id": ...}`，只在解析器找到的论文里检索，其他论文不会挤进结果里。

### 5. 本地还是在线，由条件边决定，不由模型决定

library 从"带工具的 Agent"改成了一个小的 LangGraph 子图。"走本地还是走在线"由 `route_source` 这个条件边决定，它是普通的代码判断。模型只在最后的 `answer` 节点写回答。

`library_node` 对外的接口不变：输入还是 `TaskState`，输出还是 `agent_update(...)`，所以主图 `graph.py` 完全不用改。子图外面包了一层 `try/except`，原因和 v0.2 的 `ask_agent()` 一样：在并行执行时，一个分支抛出异常，整个 superstep 都会失败。

### 6. 中间尝试过的两个方案

最终方案确定之前，"论文在不在本地"先后有过两种实现，都用同一套 library 评测跑了 3 轮：

| 方案 | 做法 | 结果 | 为什么没有采用 |
| --- | --- | --- | --- |
| A：代码匹配 + 阈值 | 一个工具，内部先匹配标题，再走带阈值的向量检索，最后回退到在线检索 | 42/42，平均每题 1,424 tokens | 4 个辅助函数加起来 40 多行，回退逻辑藏在工具内部，不好读 |
| B：多工具 | `read_paper` / `search_library` / `search_papers`，由模型串联；标题不对时，工具返回可选标题列表 | 42/42，平均每题 1,669 tokens（+17%） | 提示词里要放标题列表，无法随论文库扩展；"在不在库里"又交回给了模型判断 |

两个方案准确率相同，说明当时的 14 道题已经区分不出它们的差异。最终方案选择了"确定性路由 + 提示词里不放列表"：它在结构上就避开了 B 的扩展问题，同时比 A 更好读。

### 7. 名字匹配：别名必须是一个完整的名字

`resolve_local_paper()` 第一版只做**标题和别名的匹配**，不区分大小写，不用模型。关键是"完整的名字"怎么界定：

```python
NAME_CHAR = r"[a-z0-9+\-]"   # 能出现在论文名里的字符
pattern = rf"(?<!{NAME_CHAR}){name}(?!{NAME_CHAR})"
```

匹配到的名字前后都不能紧挨着这些字符。所以：

- "SAM" 不会误匹配 "MedSAM" 或 "Cellpose-SAM"
- "CellViT" 不会误匹配 "CellViT++"
- "HoVer-Net's limitations" 仍然能匹配到 HoVer-Net

拼写变体（"HoVerNet"、"HoVer Net"）通过在 `papers.json` 里**手动写别名**来覆盖，不自动生成。

解析器会返回**所有**匹配到的论文，而不只返回一篇，因为 "Compare CellViT and HoVer-Net" 这类问题本来就要同时查两篇。

### 8. 相似度阈值：试过了，暂时删掉

方案 A 中用过一个余弦相似度阈值（0.45），用来判断"向量检索的结果是不是真的相关"。校准时发现了两件事：

- **阈值能判断"有没有相关的论文"，但分不出"是哪一篇"。** 描述 CellViT 的查询，排第一的是 HoVer-Net（0.629 对 0.610）。
- **"相关"不等于"在库里"。** "foundation models for cell segmentation" 和 Cellpose 的相似度是 0.565，比一部分库内查询还高。所以没有任何一个阈值能把所有库内和库外查询完全分开。

现在由解析器负责判断"在不在库里"，向量检索只在已经确定的论文里取段落，所以这个阈值暂时不需要了。目前每篇论文只有 1 个 chunk，加了阈值也不会有任何效果。

以后把完整论文切成多个 chunk 时，阈值会重新派上用场，但用途变了：从判断"这篇论文在不在库里"，变成判断"这一段和问题是否相关"。到时要注意两点：

1. 两者比较的对象不同，分数分布也不同，必须重新校准，不能沿用 0.45
2. 至少保留分数最高的那一段，不能把一篇已经确认在本地的论文过滤到一段都不剩

### 9. 一个顺手修掉的 bug

OpenAlex 会把 `?` 和 `*` 当成通配符，对普通搜索直接返回 400。之前 search Agent 只传关键词，从来不带问号，所以没有暴露。现在 library 会直接把整句问题传给在线检索，比如 "What is Cellpose-SAM?"，就触发了这个 bug。`search_openalex()` 现在会先去掉这两个字符再发请求。

## 评测结果

| 评测 | 题数 | 结果 |
| --- | --- | --- |
| 路由（改动前，3 轮） | 34 | 100/102（98%），Mask R-CNN 有 2/3 被分错 |
| 路由（改动后，3 轮） | 35 | 105/105，每道题 3 轮结果都一致 |
| library（最终方案，1 轮，路由是确定性的） | 18 | 16/18，平均每题 5.8s、1,336 tokens |

library 错的 2 道都是"只描述、不点名"的问题，例如 "Which paper uses star-convex polygons to detect nuclei?"。按标题和别名匹配找不到这类问题，所以它们会被判为本地没有，转去在线检索。这是第一版明确不做的部分。

## 已知局限

| 局限 | 例子 | 可能的方向 |
| --- | --- | --- |
| 只描述不点名的问题找不到本地论文 | "Which paper uses star-convex polygons?" 走了在线检索 | 对元数据（标题、别名、摘要）做语义检索 |
| 在线检索直接用整句问题 | "What is Cellpose-SAM?" 只搜到 CellSAM 和 μSAM | 去掉问句词，或从问题中提取论文名后再检索 |
| 本地论文和未知论文混在一起时，未知的那一半会丢 | "Compare CellViT and Mask R-CNN" 找到 CellViT 就走了本地，Mask R-CNN 没有被检索 | 按论文逐个决定走本地还是在线，最后合并 |
| 一篇论文只有 1 个 chunk | 按 `paper_id` 过滤后，返回的就是整篇摘要 | 放入完整论文、切成多段后，按段检索，再加上段落级阈值 |
| 别名要手动维护 | 新增论文时要在 `papers.json` 里补写别名 | 先保持手动；论文多了以后再考虑自动生成别名 |
| v0.2 的局限仍然存在 | 不支持串行依赖、没有对话记忆、忽略 "recent" | 见 docs/v0.2.md |

## 思考题（下一版的起点）

1. 方案 A 和方案 B 在 14 道题上都是 42/42。你能构造出一道题，让两者结果不同吗？比如一篇和库里论文名字很像、但其实不在库里的论文。如果构造不出来，"用模型还是用代码"应该根据什么来决定？
2. 解析器现在只做精确的别名匹配。如果第二版加了元数据语义检索，"star-convex polygons" 能找到 StarDist，但 "foundation models for cell segmentation" 也可能被误判为 Cellpose。这一层应该怎么组合：精确匹配优先，语义检索兜底？阈值又该怎么校准？
3. "Compare CellViT and Mask R-CNN" 需要本地和在线各查一部分。现在的条件边只能二选一，要支持这类问题，子图应该改成什么样？v0.2 里用过的 `Send` 能用在这里吗？
